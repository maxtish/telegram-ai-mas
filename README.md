# 🇩🇪 AI German Tutor Bot (Multi-Agent System)

Умный Telegram-бот для изучения немецкого языка, построенный на базе мультиагентной LLM-архитектуры (OpenAI) и очередей (BullMQ). Бот имитирует живого человека из Германии со своей уникальной личностью, графиком работы и способностью проявлять инициативу.

## 🚀 Основные фичи (Features)
- **Живая личность (Persona):** При первом запуске бот генерирует себе уникальное имя, возраст, профессию, город проживания и стиль общения. Он отыгрывает эту роль во всех диалогах.
- **Умный Диспетчер (Smart Inbox):** Бот не отвечает на каждое сообщение слепо. Он ждет 10 секунд (Debounce), собирая серию сообщений, а затем решает: ответить сейчас, отложить ответ (если бот "на работе"), проигнорировать (если это просто "Ок") или подождать (если юзер занят).
- **Проактивность (Planner):** Бот умеет писать первым. Каждое утро (08:00) он планирует свой день и в случайное время может написать, чтобы поделиться историей или спросить, как дела.
- **Интервальное повторение (Spaced Repetition):** Полноценная система изучения слов с алгоритмом умных карточек, распознаванием опечаток и синонимов.
- **Фоновый анализ грамматики (Teacher):** Каждые 5 сообщений скрытый агент анализирует речь пользователя, находит грамматические ошибки и сохраняет правила для их исправления.
- **Языковой патруль:** Если пользователь ленится и пишет обычные сообщения на русском (а не просит объяснить правило), бот с юмором отчитывает его и заставляет перевести текст на немецкий.

## 🏗 Архитектура (Multi-Agent System)

Проект разбит на независимых агентов, каждый из которых выполняет свою узкую задачу:

1. **`Communicator` (Общение):** Отвечает за естественный диалог. Имеет жесткую инструкцию *не заканчивать каждое сообщение вопросом*, чтобы общение не выглядело навязчивым.
2. **`Dispatcher` (Анализ входящих):** Секретарь бота. Читает накопившиеся за 10 секунд сообщения и принимает решение (Action):
   - `reply_now`: ответить сразу.
   - `delay`: отложить на X минут (бот спит или на работе).
   - `ignore`: проигнорировать ("Ок", смайлики).
   - `user_busy`: пользователь попросил подождать ("секундочку") -> бот ставит таймер-пинг на 10 минут.
   - `enforce_german`: пользователь говорит по-русски не по делу -> сделать шуточный выговор.
3. **`Planner` (Расписание):** Генерирует события на день (поход в магазин, кофе-брейк) и ставит задачи в `BullMQ` для проявления инициативы.
4. **`Teacher` (Учитель):** Анализирует грамматику пользователя в фоне.
5. **`Dictionary` (Словарь):** Извлекает слова из сообщений пользователя, переводит их (с добавлением артиклей) и сохраняет в БД. Содержит функцию `/fixdb` для починки битых записей.
6. **`Examiner` (Экзаменатор):** Проводит квизы по словарю. Отличает опечатки от полного незнания, дает подсказки и управляет графиком повторения слов.

## 🧠 Ключевые алгоритмы

### 1. Накопитель сообщений (Debounce)
- Telegram не передает статус "печатает...". Чтобы не перебивать пользователя, бот при получении текста ставит таймер на 10 секунд (`jobId: reply-ID`).
- Если приходит новое сообщение — старый таймер удаляется, и отсчет 10 секунд начинается заново.
- Только после наступления тишины вызывается `Dispatcher`.

### 2. Алгоритм интервального повторения (Spaced Repetition)
Каждое слово имеет счетчик знания `score` (от 0 до 5) и дату следующего повторения `nextReview`.
- **Интервалы:** 10 минут -> 4 часа -> 24 часа -> 3 дня -> 7 дней.
- **Оценка LLM:** Экзаменатор получает ответ и возвращает статус:
  - `correct`: `score` + 1, дата сдвигается вперед.
  - `typo`: `score` не меняется, юзеру дается второй шанс исправить опечатку (состояние сессии сохраняется).
  - `wrong` (или "weiß nicht"): `score` сбрасывается в 0, слово вернется через 10 минут.

### 3. State Machine (Управление состояниями)
Поле `botState` в модели `User` определяет, как бот реагирует на текст:
- `IDLE`: Обычный режим (работает Debounce и Dispatcher).
- `WAITING_WORDS`: Бот ждет список слов для добавления в словарь (отключает Dispatcher).
- `QUIZ_SESSION` (JSON): Режим сессии тренировки. В состоянии хранится очередь слов, текущее слово, количество правильных/неправильных ответов. Бот не выходит из режима, пока не кончится очередь (до 20 слов) или не нажата кнопка отмены.

## 🛠 Технический стек

- **Node.js (v20)** + **TypeScript**
- **Telegraf** (Telegram Bot Framework)
- **Prisma ORM** + **PostgreSQL** (База данных)
- **BullMQ** + **Redis** (Очереди задач, таймеры, Cron-джобы)
- **OpenAI API** (`gpt-4o-mini` для всех агентов, экономно и быстро)

---

## 🗄 Структура Базы Данных (Prisma)

- **`User`**: Хранит `telegramId`, языковые настройки и текущий `botState`.
- **`Persona`**: Привязана к User. Хранит сгенерированную личность бота (имя, профессия, город, стиль общения).
- **`Message`**: История переписки (`sender: BOT | USER`, `content`). Используется как контекст для LLM.
- **`Vocabulary`**: Словарь пользователя. Поля: `wordOrRule`, `translation`, `score`, `nextReview`.

## ⚙️ Управление и Интерфейс

### Клавиатура (Main Menu)
- **📘 Добавить слова:** Переводит бота в режим словаря. Извлекает слова и переводит их.
- **🧠 Повторять слова:** Запускает `QUIZ_SESSION` — экзамен на 20 слов с формированием финального отчета.
- **📜 Мой словарь:** Выводит весь список слов пользователя с визуализацией прогресса (🟢🟢⚪⚪⚪), разбивая на части при превышении лимита символов Telegram.

### Команды (Скрытые)
- `/start` — Инициализация, создание Persona, выдача клавиатуры.
- `/plan` — Ручной запуск планировщика на сегодня (для тестов).
- `/quiz` — Ручной запуск экзамена на 1 слово.
- `/fixdb` — Ремонт словаря (ищет слова со сломанным `translation = null` и переводит их заново).

### Фоновые задачи (Cron)
- **08:00 (Берлин):** Запуск Сценариста (`daily-planner`), генерация плана на день.
- **09:00 - 21:00 (Ежечасно):** Авто-квиз. Бот сам выбирает слово, убеждается, что диалог сейчас не активен (тишина более 15 минут), и присылает проверочный вопрос.

## 📂 Структура проекта

```text
ai-bot/
├── prisma/
│   └── schema.prisma          # Схема БД (таблицы User, Persona, Message, Vocabulary)
├── src/
│   ├── agents/                # Папка с ИИ-агентами (мозги бота)
│   │   ├── communicator.ts    # Общение в диалоге (с запретом задавать лишние вопросы)
│   │   ├── dictionary.ts      # [НОВЫЙ] Парсинг новых слов, перевод и команда /fixdb
│   │   ├── dispatcher.ts      # Оценка входящих сообщений, языковой патруль и Debounce
│   │   ├── examiner.ts        # [НОВЫЙ] Проверка ответов на квиз, алгоритм Spaced Repetition
│   │   ├── planner.ts         # Планирование дня бота и генерация событий
│   │   └── teacher.ts         # Фоновый анализ грамматики каждые 5 сообщений
│   ├── workers/               
│   │   └── scheduler.ts       # BullMQ Воркер: очереди ответов, Cron-задачи, авто-квизы
│   ├── database.ts            # Инициализация подключения к БД (Prisma Client)
│   └── index.ts               # Точка входа: Telegraf, обработка кнопок и логика State Machine
├── .env                       # Токены (TELEGRAM_BOT_TOKEN, OPENAI_API_KEY, DATABASE_URL)
├── package.json               # Зависимости проекта
└── tsconfig.json              # Настройки TypeScript
```
